# Встроенный язык SimInTech

Справочник целиком: `https://github.com/producedbysavant/simintech-code/blob/main/` (`language/`, `blocks/`,
`patterns/`, `tutorials/`). Здесь — то, что чаще всего ломает работу агента.

**Официальная справка:**
[Язык программирования SimInTech](https://help.simintech.ru/11_yazyk_programmirovaniya/KEY_yazik_programmirovania.html)
— первоисточник по синтаксису и функциям.

## Когда нужен этот язык

Рекомендованный вендором путь построения схемы скриптом: `createblock`,
`createmodel`, `savemodeltofile` (разбор — в разделе «Построение модели
встроенным языком» ниже). Нужен он и для классов, которые отвергает библиотека:

- «Из памяти»
- «Порт выхода»

`CreateBlock` их создаёт — обе записи, с ненулевым id (замерено 2026-09-18), —
но годность в расчёте не проверена, и отказ идёт от библиотеки, а не от COM.

См. набор `UNSUPPORTED_COM_BLOCK_CLASSES` в
[`simintech_api/constants.py`](https://github.com/producedbysavant/simintech-code/blob/main/simintech_api/constants.py).
Синтаксис `файл.py:ИМЯ` якоря на символ в GitHub не работает — ссылка даёт 404.

Блоки библиотеки «Конечные автоматы» языку **не** требуются: они создаются
через `CreateBlock` — но только по полному имени записи с префиксом
«Конечные автоматы - » (например, `Конечные автоматы - Флаг входа в
состояние`); короткий заголовок с палитры (`Флаг входа в состояние`)
`CreateBlock` не принимает. Собрать автомат целиком через MCP всё равно нельзя
(состояния живут на внутренней странице карты) — см. скилл
`simintech-model-building`.

## Синтаксис — Pascal, не C

**Самая частая ошибка** — писать C-подобный код.

| Неправильно (C) | Правильно (SimInTech) |
|---|---|
| `==` | `=` |
| `!=` | `<>` |
| `&&` `\|\|` `!` | `and` `or` `not` |
| `{ }` как блок кода | `begin ... end;` |
| `//` в конце строки без `;` | обязательна `;` |

Полный набор операторов:

- арифметика: `+ - * /`, `div` (целочисленное), `mod` (остаток)
- сравнение: `= <> < > <= >=`
- логика: `and or not xor`
- биты: `shl shr`

## Функции языка — по реестру, не по догадке

Правдоподобные имена (`tan`, `asin`, `pow`) в языке **отсутствуют** — в
реестре справки таких записей нет. Существование имени проверяется по реестру
[`simintech_api/data/language_functions.json`](https://github.com/producedbysavant/simintech-code/blob/main/simintech_api/data/language_functions.json),
поиск по имени — `simintech_api.language.find_function`. Реестр отвечает, есть
ли такое имя, и даёт его назначение, но **не** даёт сигнатур — порядок
аргументов по нему не узнать; угаданное имя всплывёт только на кодогенерации.

## Область видимости и объявления

```simintech
input u: double;
output y: double;
const k = 2.5;
var counter: integer;

begin
    y = u * k;
end;
```

Правила:

- **Регистр не различается**: `Speed` и `speed` — одно и то же
- **У каждой переменной явный тип**: `var a: double, b: double;`
- **Запрещены имена `i`, `j`, `c`** — конфликтуют с авто-счётчиками транслятора
- `var` сохраняет значение между расчётными шагами
- Код исполняется на каждом расчётном шаге

## Типы

| Тип | Кодогенерация |
|---|---|
| `double`, `integer`, `boolean` | ✅ |
| `array`, `intarray` (только статические) | ✅ |
| `string` | ❌ не генерируется |

## Комментарии

`{ ... }` — блочный, `//` — до конца строки.

## Подводный камень: генерация Pascal-кода в `.inc`

Если строите Pascal-код строками в секции `beforecompile`, у языка выражений
**нет экранирования кавычек** — литерал `"` внутри строки закрывает её
досрочно, и остаток кода парсится как выражения. Симптом: «Символ X не может
быть использован» или «Ключевое слово if задано неверно» для символа, который
виден внутри строки.

Правило: одна строка — одно выражение; для встраиваемых Pascal-литералов
используйте `quotes = chr(34)`, для переводов строк — `CLRF`.

## Построение модели встроенным языком

**Рекомендованный вендором путь.** По сообщению технической поддержки вендора
(2026-09-28) собирать схему предлагается именно языком, а не вызовами
построения через COM. Весь цикл закрывают четыре функции:

| Функция | Что делает |
|---|---|
| `createblock` | Создать блок по **полному имени записи** библиотеки; отказ — `0` |
| `createmodel(projectid, model)` | Создать модель из декларативного текста |
| `savemodeltofile(projectid, path)` | Выгрузить текущий контейнер в текст |
| `createmodelfromfile` | Создать модель из текстового файла |

`createblock` есть и в официальной справке
([createblock](https://help.simintech.ru/11_yazyk_programmirovaniya/6_funkcii/3_graficheskie_i_sistemnye/obekty/createblock.html)):
`obj_id = createblock(id, class_name)`, есть варианты с владельцем
(`parent_id`) и номером слоя (`layer_nmb`); класс берётся из подключённой
библиотеки, имя — **с учётом регистра**. Требование к имени то же, что у COM:
полное имя записи, а не короткий заголовок с палитры
(см. `simintech-model-building`).

`createmodel`, `savemodeltofile` и `createmodelfromfile` в справке вендора на
момент замера ещё не описаны: они получены по сообщению технической поддержки
вендора (2026-09-28) и проверены живым замером на поставке 2.26.6.23. Отсюда
рабочий порядок — **выгрузить, поправить, загрузить**:
`savemodeltofile` отдаёт и содержимое контейнера, и образец синтаксиса, а
`createmodel` принимает такой же текст обратно. Формат по памяти не сочиняют.

Доставка скрипта в проект — отдельный риск: COM-метод `SetPageScript` кладёт код
в **текущую** страницу и возвращает `1` даже при синтаксически неверном скрипте,
а ошибка наружу не сообщается вовсе. Признак успеха — не код возврата, а то, что
скрипт записал в файл
([simintech_api/core/script_bridge.py](https://github.com/producedbysavant/simintech-code/blob/main/simintech_api/core/script_bridge.py)).

## Декларативный текст модели

Записи «симулинковского вида»: объект — имя, класс, точки и свойства; провод —
отдельная запись со ссылками на порты концов; вложенный контейнер — вложенная
запись.

```text
Имя: (type = "Класс", points = [...], свойства)
Имя: (type = "wire", src = "block:out:0", dst = "block:in:0")
Имя: (subsystem: ( … ))
```

Как это читается: `type` — класс из библиотеки; `points` — точки объекта на
схеме; остальные поля внутри скобок — свойства блока, и имена у них сверяйте с
каталогом (`simintech-model-building`), а не с догадкой. В `src` и `dst` порт
адресован тремя частями: имя блока, сторона (`out`/`in`) и номер порта.
`subsystem` вместо `type` — признак вложенного контейнера; его содержимое лежит
на своём уровне вложенности.

Полей здесь ровно столько, сколько нужно, чтобы прочитать выгрузку. Остальное
даёт `savemodeltofile` на реальном контейнере — не догадка.

## Ветвление: `src = "имя_линии:K"`

Ветвь отходит не от блока, а от **точки** уже существующей линии: в `src`
пишется имя родительской линии и номер точки, **с нуля**.

```text
branch_0: (type = "wire", src = "wire_0:0", dst = "kx_1:in:0")
```

В COM той же паре соответствует `getparentwireid` (сама родительская линия) и
`getparentwirenodeindex` (номер узла), и там счёт **на единицу больше**: точка
`K` из текста — это узел `K + 1` (`node = point_nmb + 1`). Число, взятое из
текста без поправки, укажет на соседний узел.

**Без промежуточных точек ветви неразличимы.** У линии без точек перегиба все
ветви ссылаются на одну и ту же запись линии, и отличить их нечем — место
отвода в записи не выражено. Поэтому главной линии точки задают заранее, в её
`points`, и только к ним подключают ветви.

## Правила среды: где отказ молчаливый

Замер 2026-09-28, поставка 2.26.6.23. Ни одно из этих правил не видно из текста
скрипта: среда либо пишет в окно сообщений, либо молчит — отказ приходит
нулевым id, а не ошибкой.

- **Создавать объекты можно только в секции `initialization` скрипта страницы.**
  Её операции выполняются один раз при запуске расчёта
  ([initialization](https://help.simintech.ru/11_yazyk_programmirovaniya/5_klyuchevye_slova/sekcii/initialization.html)),
  всё вне секции идёт на каждом шаге — и создавать объекты тогда нельзя: среда
  отвечает «Установка блока на схему в процессе моделирования запрещена», а
  `createblock` возвращает `0`, то есть отказ выглядит как обычный нулевой id.
- **`createprimitiv` доступна только в графическом контейнере.** Из макроса
  среда отвечает «Функция createprimitiv не найдена»; вендорская справка и
  перечисляет её среди
  [функций, доступных только в графическом контейнере](https://help.simintech.ru/11_yazyk_programmirovaniya/funkcii_dostupnye_tolko_v_graf_konteinere.html).
  По блочному коду она создаёт объект **без портов**: порт задаётся отдельно —
  `setprop(obj, "PortNames", "<имя>")`, затем `initobject(obj)`.
- **`TAB` — предопределённая константа.** Присваивание `TAB = …` в секции ломает
  компиляцию скрипта, и видно это **только в окне сообщений**: через COM оно не
  читается, а расчёт при этом стартует молча. Проверить заранее нечем — имя
  `TAB` под свою переменную просто не занимают.
- **Внешние порты субмодели создаются на её странице.** `getsubmodelid` даёт
  страницу субмодели, `createblock(contid, "Порт входа")` и `"Порт выхода"` —
  сами порты. Видны они не в `initialization`, а с первого шага расчёта:
  подтвердить их существование сразу после создания нечем.
- **`traceallports(port, 1)` проходит через границу контейнера.** Второй
  аргумент `1` включает обход сопряжённых портов, и соседей становится видно в
  том числе в субмодели; с `0` остаётся только внешний сосед. В справке функция
  дана с одним аргументом (`traceallports(port_id)`) — вариант с двумя измерен
  2026-09-28.
