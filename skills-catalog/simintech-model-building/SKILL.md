# Построение модели SimInTech

## Порядок работы

```
create_project(end_time=N) → add_block → connect → layout_place
  → get_block_params → set_block_param → run(to_time=N) → read_output_file
```

`create_project` создаёт проект **из шаблона** («Схема модели общего вида») —
только такой проект считает. `end_time` (или `set_calc_time`) задаёт конечное
время расчёта; по умолчанию — из шаблона, 10 с. Почему пустой проект не
считает — §18 карты API
([com_api_inventory.md](https://github.com/producedbysavant/simintech-code/blob/main/docs/reference/com_api_inventory.md)).

Результат удобнее всего снимать блоком «В файл» и читать `read_output_file`
(см. скилл `simintech-simulation`).

**Соединяйте все входы.** Блок с неподключённым входом молча останавливает
расчёт всей модели: `get_time()` остаётся `0.0`, ошибки нет. Это первое, что
надо проверить, если «расчёт не идёт».

`layout_place` считает координаты `LayeredPlacer` **и применяет их** к блокам.
Принимает имена или id; обе стороны каждой связи должны быть в `block_ids`,
иначе инструмент отказывает (а не «расставляет» несуществующие блоки):

```
layout_place(block_ids="k_0,kx_0,ToFile_0", connections="k_0->kx_0,kx_0->ToFile_0")
```

## Имена свойств — короткие

**Главная ловушка.** Имена свойств в SimInTech короткие и нечитаемые:

| Класс | Реальные параметры |
|---|---|
| Константа | `a`, `src_type`, `txt`, `formula_visible` |
| Усилитель | `a` |
| Сумматор | `a` (массив весов). Число входов длина массива **не** задаёт — их меняет `in_ports` у `add_block` |
| Интегратор | `k`, `x0` |
| Производная | `x0`, `resetport` |
| Ступенька | `t`, `y0`, `yk` |
| Синусоида | `a`, `w`, `f` |
| Сравнивающее устройство | `a` |
| любой | `Name` |

Это выжимка по ходовым классам, а не копия справочника: полный набор имён
класса дают ресурс `simintech://blocks/catalog` и `get_block_params(block="k_0")`
у созданного блока. Имена в таблице сверяет с каталогом тест — молча
разъехаться с источником она не может.

Проверено на реальном SimInTech. Это **не** `value`, `gain`, `signs`,
`numInputs`, `reset`. Обратите внимание: у «Константы» параметр — **`a`**, а
не `y0`; у «Сумматора» **нет** `xn`.

Документация `https://github.com/producedbysavant/simintech-code/blob/main/blocks/` использует читаемые имена —
они не совпадают с реальными, опираться на неё нельзя.

Проверить доступные имена: `get_block_params(block="k_0")`. Он читает имена
из каталога блоков (`https://github.com/producedbysavant/simintech-code/blob/main/simintech_api/data/block_catalog.json`).

Состав и назначение блоков — [Библиотеки блоков](https://help.simintech.ru/10_biblioteki_blokov/KEY_biblioteki_blokov.html)
в официальной справке.

## Формат значений

`add_block` и `set_block_param` принимают `props` / `value` строкой:

```
add_block "Константа" props="a=5"
add_block "Сумматор" props="a=[1, -1]"
```

Параметр `name_hint` имени **не применит**: COM не переименовывает блоки, имя
остаётся автоматическим (`k_0`, `kx_0`). Ответ инструмента всегда сообщает
фактическое имя — используйте его в `connect`, `get_block_params`,
`layout_place`.

- скаляры: `a=2`, `y0=5`, `k=1.5`
- массивы: в стиле SimInTech — `a=[1, -1]`
- знаки сумматора кодируются весами: `[1, -1]` — вычитание

## Классы, которые отвергает библиотека

`constants.UNSUPPORTED_COM_BLOCK_CLASSES` (2): **«Из памяти»** и
**«Порт выхода»**. `CreateBlock` создаёт обе записи и возвращает ненулевой id —
замерено на живом COM 2026-09-18. Отказывает уже библиотека: годность этих
блоков в расчёте не проверена, поэтому `Page.create_block` поднимает
`UnsupportedBlockError`. Пока пригодность не подтверждена, для них остаётся
встроенный язык SimInTech (см. скилл `simintech-language-core`).

Не путать два утверждения: создание **подтверждено**, а годность в модели — нет.
Снятие запрета зависит от замера пригодности, а не от COM.

Проверенно создаваемые классы (`SUPPORTED_COM_BLOCK_CLASSES`, 13):
«Константа», «Усилитель», «Сумматор», «Интегратор», «Производная»,
«Ступенька», «Синусоида», «Временной график», «Сравнивающее устройство»,
«Порт входа», «Задержка на шаг интегрирования», «RS-триггер с приоритетом по
установке», «В файл».

Список — в коде
([`simintech_api/constants.py`](https://github.com/producedbysavant/simintech-code/blob/main/simintech_api/constants.py)), он же источник истины; здесь
приведён для ориентира.

## Библиотека «Конечные автоматы»

Блоки этой библиотеки через COM **создаются** — но только по **полному имени
записи**, с префиксом «Конечные автоматы - » (`constants.FSM_RECORD_PREFIX`,
`FSM_BLOCK_RECORDS` / `fsm_record()`):

```
add_block(class_name="Конечные автоматы - Состояние автомата")
```

Короткий заголовок с палитры (`Состояние автомата`) `CreateBlock` не
принимает и возвращает 0: заголовок и имя записи в библиотеке — разные вещи.

Собрать автомат целиком через MCP нельзя: карта состояний (`Конечные автоматы -
Карта состояний конечного автомата`) создаётся на главной странице, а состояния
живут на её внутренней странице (`GetSubmodelPage`), инструмента для которой у
сервера нет. Порядок сборки и связи переходов (класс `КА - Связь блоков
состояний`) — §5 карты API
([com_api_inventory.md](https://github.com/producedbysavant/simintech-code/blob/main/docs/reference/com_api_inventory.md)).

## Смена параметра существующего блока

`set_block_param(block, param, value)` устанавливает свойство **и
переинициализирует блок** (`InitBlock`). Переинициализация обязательна:
карта COM API прямо отмечает, что `SetBlockProp` может не повлиять на расчёт,
потому что блоки вроде «Константа» инициализируются до `ProjectStart`.

**Имя сверяется с каталогом до записи.** Если у класса, который в каталоге
есть, такого параметра нет, инструмент отвечает отказом (`isError`), и запись
в COM не уходит вовсе — в сообщении перечислены известные имена. Тем же
отказом заканчивается запись в вычисляемый параметр (его значение задаёт
среда, `SetBlockProp` его не меняет — запись была бы молчаливой). Проверка
обязательна: сам `SetBlockProp` **не отвергает неизвестное имя** — параметр
«устанавливается», ошибки нет, а расчёт идёт по старому значению.

Осознанный обход — `allow_unknown=True` (у `add_block` —
`allow_unknown_props=True`): сверка с каталогом снимается, имя пишется как
есть. Применяйте его, только когда уверены, что параметр существует, —
например, каталог отстаёт от сборки. Иначе это та же запись в никуда, но уже
без единого сигнала.

Примечание о непроверенном имени приходит **в успешном ответе** только тогда,
когда проверить нечем: класса нет в каталоге (или каталог недоступен целиком).
Здесь значение действительно записывается — что оно влияет на модель,
подтвердит только расчёт.

## Ошибки инструментов

Отказ инструмента приходит **исключением**, а в ответе протокола — флагом
`isError`. Раньше ошибка возвращалась строкой `"ERROR: ..."`, и клиент,
доверявший флагу, видел успех там, где ничего не произошло. Проверяйте
`isError`, а не текст ответа; текст отказа — в сообщении ошибки.

Обратная сторона: успешный ответ **не** означает, что действие дало эффект.
`step` и `run(to_time=…)` **отказывают** (`isError`), если модельное время не
сдвинулось, — читайте сообщение отказа, а не только флаг. А `run()` без
`to_time` и `stop()` успех возвращают, но эффект не подтверждают: проверяйте
результат по времени или по данным.

## Встроенный язык — путь, который вендор называет для сборки схемы

Этот скилл описывает COM-путь. В ответе технической поддержки вендора
(2026-09-28) для сборки схемы назван встроенный язык: `createblock` создаёт блок
по **имени класса** из подключённой библиотеки (полное имя записи),
`savemodeltofile` — выгружает текущий контейнер обратно в текст, `createmodel`
и `createmodelfromfile` — создают модель из текста. Требование к имени класса
там то же, что у `CreateBlock` (см. раздел о конечных автоматах выше), а отказ,
измеренный на установке блока во время расчёта, приходит нулевым id, а не
ошибкой.

**Загрузка текста работает** — но с одной ловушкой: кавычка внутри строкового
литерала задаётся `chr(34)`. Удвоение `""` в этой сборке даёт **пустую строку**,
а обратный слэш не экранирует; текст при этом выглядит правдоподобно, объектов
не создаёт и сообщений не оставляет. Наш прежний отрицательный результат
(`createmodelfromfile` «не работает») был ошибкой на нашей стороне. Замер
2026-09-29: `savemodeltofile`, `createmodel`, `createmodelfromfile` проходят на
поставке 2.26.6.23 — пять демонстрационных проектов вендора и своя проба.
Семейство функций текста модели вендор называет из **четырёх** имён — вместе с
`savemodeltotext`; последней в поставке 2.26.6.23 мы не нашли, поэтому на это имя
в сценарии не опирайтесь (подробности — в скилле `simintech-language-core`).

**Доставка скрипта и сборка текстом — через MCP-сервер.** `import_model_text`
собирает модель из текста, `export_model_text` выгружает её обратно,
`set_page_script` и `run_page_script` ставят скрипт в страницу: тело идёт в
секцию `initialization`, где создавать объекты разрешено, а прежний скрипт
возвращается на место. Исходы и порядок шагов — в скилле `simintech-language-core`,
раздел «Контур».

**Полный порядок сборки — в примере.** Реплики для агента, что сверяет человек
по шагам и какие четыре случая обязаны отказать внятно:
[`docs/examples/language-contour.md`](https://github.com/producedbysavant/simintech-mcp/blob/main/docs/examples/language-contour.md).
