# Блок «Язык программирования»: шаблон и формат скрипта

Блок «Язык программирования» (ЯП) — место в модели, где логика пишется кодом
на встроенном языке: скрипт исполняется **на каждом шаге расчёта** и, если для
проекта делается кодогенерация, транслируется в C. Синтаксис языка и правила
среды — в скилле `simintech-language-core`; разбор ошибок компиляции,
трансляции и времени выполнения — в `language/pitfalls.md` (ссылки в
манифесте). Здесь — **структура скрипта блока**: порядок секций, каркас,
что в какую секцию кладут и по какому чек-листу проверяют.

## Каркас

Порядок секций выверен под кодогенерацию: объявление — до первого
использования, в частности константы размеров портов — до `input`/`output`.

```simintech
const                // 1) размеры массивов-портов — ДО input/output
    NWAG = 20;

input                // 2) входные порты (тип у каждого явно)
    cmd: double,
    flags[NWAG]: intarray;

output               // 3) выходные порты
    y: double,
    dbg_phase: integer;      // отладочный выход — вместо seterrorstr

const                // 4) остальные константы
    EPS = 1e-12;

var                  // 5) переменные, сохраняемые между шагами
    sum: double,
    initialized: boolean;

// include "путь/файл.pas";   // 6) после объявлений, от которых зависит

initialization       // 7) один раз при инициализации модели
    sum = 0;
    initialized = false;

begin                // 8) тело расчёта — каждый шаг
    if not initialized then
        initialized = true;
    // ...
end;
```

Секции обрабатываются **последовательно, сверху вниз**: константа или
переменная обязана быть объявлена до первого использования. Отсюда два
следствия, которые чаще всего и нарушают:

- размер массива-порта (`input cnd[M]: double`) требует константы `M`
  **до** секции `input`;
- `include`, зависящий от переменных основного файла, ставится **после**
  их объявления.

`initialization` исполняется один раз (до первого шага) — там место
копированию входных массивов и сбросу состояния. `var` сохраняет значение
между шагами; секция `finalization` — один раз по завершении расчёта
(закрыть файл, выгрузить накопленное).

## Входные и выходные порты

- Тип указывается **у каждого** имени отдельно: `var a, b, c: double;`
  недопустимо — каждая строка с типом.
- Массивы — только статические и с размером: `flags[NWAG]: intarray`;
  динамические (`var R: array`) в C не транслируются.
- Входной массив **нельзя изменять** — он принадлежит источнику сигнала.
  Если логика модифицирует данные — при инициализации скопировать во
  локальный массив поэлементно.
- Вход может быть **пустым** (автономный запуск): код обязан проверять
  `lengthofm(входной_массив) > 0` и выходить, а не падать.
- `lengthofm()` возвращает **объявленный** размер статического массива, а не
  фактическое количество данных, — реальную длину храните отдельной
  переменной.
- Индексация — **с единицы**; арифметику внутри `[ ]` не применять
  (`arr[curI - 1]` — нельзя, сначала переменная).

## Кодогенерация: что не транслируется в C

Не переводится и обрывает генерацию (или молча искажается): `#`, `&`, `..`,
строки (`string`), записи (`record`), `seterrorstr()`, `flip()`, динамические
массивы, арифметические выражения внутри индексов, матричные операции
(`*`, `\`, `./`), прямое присваивание массивов. Взамен — циклы, поэлементное
копирование, выходные сигналы. Подробный разбор каждого случая — в
`language/pitfalls.md` (§3, §7).

## Диагностика и отладка

- В транслируемом коде `seterrorstr` использовать нельзя: диагностика —
  **выходным сигналом** и `exit` (см. `pitfalls.md` §3.6).
- Отлаживают дополнительные выходные сигналы (`dbg_phase`, `dbg_idx`,
  `dbg_len`): они видны в расчёте и в сгенерированном коде.
- Сообщения генератора указывают объект, из-за которого возникли; после
  правок прогоняйте «Инструменты → Сгенерировать программу» и разбирайте
  **все** предупреждения и ошибки.
- Если генерации нет, ошибки компиляции скрипта блока наружу (в COM) не
  выходят — признак только косвенный (расчёт не идёт).

## Чек-лист перед кодогенерацией

- [ ] порядок секций: константы размеров портов до `input`/`output`,
      `include` после своих зависимостей;
- [ ] каждая переменная с явным типом; массивы статические, с размером;
- [ ] нет имён `i`, `j`, `c`; индексы — переменные, без выражений в `[ ]`;
- [ ] деление защищено от нулевого знаменателя (порог вида `1e-12`);
- [ ] `sqrt()` — от неотрицательного аргумента (`sqrt(abs(x))`);
- [ ] границы массива проверены перед доступом;
- [ ] `while` ограничен счётчиком итераций;
- [ ] входные массивы скопированы в локальные, если изменяются;
- [ ] нет `seterrorstr`, `#`, `&`, `..`, строк и записей;
- [ ] кодогенерация прогнана, предупреждений и ошибок нет.

## Где живёт скрипт блока

Текст скрипта — свойство блока `Script`; в выгрузке модели
(`export_model_text`) он виден в записи блока. Отдельного MCP-инструмента
чтения/записи скрипта блока пока нет — правка идёт переимпортом модели
(issue simintech-mcp#23), поэтому вносите правки осознанно и проверяйте
расчётом.
