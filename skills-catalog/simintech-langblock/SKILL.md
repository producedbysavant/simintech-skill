# Блок «Язык программирования»: каркас и правила скрипта

Блок «Язык программирования» (ЯП) — место в модели, где логика пишется кодом
на встроенном языке: скрипт исполняется **на каждом шаге расчёта** и, если для
проекта делается кодогенерация, транслируется в C. Синтаксис языка и правила
среды — в скилле `simintech-language-core`; канон языка и разбор типовых
ошибок — в репозитории `simintech-code` (`language/syntax.md`,
`language/pitfalls.md`, `language/keywords.md`; ссылки в манифесте). Здесь —
**собранный каркас блока**: порядок объявлений, порты и массивы, что не
переживает трансляцию, и чек-лист перед генерацией.

## Каркас

Порядок объявлений — канонический (syntax.md): **входы → выходы → константы →
переменные**, затем необязательная секция `initialization` и тело расчёта.
Каждая секция закрывается `end;`.

```simintech
input                // 1) входные порты (тип у каждого имени явно)
    cmd: double,
    flags[3]: intarray;

output               // 2) выходные порты
    y: double,
    dbg_phase: integer;      // отладочный выход — вместо seterrorstr

const                // 3) константы
    EPS = 1e-12;

var                  // 4) переменные, сохраняемые между шагами
    sum: double,
    initialized: boolean;

initialization       // 5) один раз при запуске расчёта
    sum = 0;
end;

begin                // 6) тело расчёта — каждый шаг
    if initialized = false then
    begin
        // однократная загрузка: копирование входных массивов и т. п.
        initialized = true;
    end;
    // ...
end;
```

**Однократная загрузка — по флагу в теле, а не в `initialization`.** В секции
`initialization` порты субмоделей могут быть ещё не установлены (канон,
`syntax.md`); поэтому копирование входных массивов и всё, что зависит от
входов, делают на первом шаге под флагом (шаблон — `keywords.md`: переменная
`var initialized`, загрузка `if initialized = false then … initialized = true`).
Переменные секции `var` обнуляются при старте расчёта — объявлять
`initialized = false` вручную не нужно.

## Порты и массивы

- Тип указывается **у каждого имени**: `cmd: double, flags[3]: intarray`;
  запись `var a, b, c: double;` (один тип на список имён) недопустима.
- Массивы — только статические, размер — литерал или константа:
  `flags[3]: intarray`. Динамические массивы не транслируются.
- **Порт-массив: форма с размером в скобках пересборку не проходит**
  (живой замер 02.10.2026, блок с тремя входами: `a[3]: array` дал
  **два** входа вместо трёх, а `a: array` — все три, и модель с ним
  считалась). Скелет выше (`flags[3]: intarray` во входе) этой проверкой
  не покрыт: если порт-массив не появляется после `reinitlangblock` —
  пробуйте форму без размера. У `var`-массивов размер обязателен
  (константа) — там правило прежнее.
- **`lengthofm` — про объявленную размерность.** У массива с объявленным
  размером (`flags[3]`) она возвращает объявленный размер; у входа **без
  размерности** длина — переменная величина, зависящая от пришедшего сигнала
  (справка вендора). Проверка «вход пуст» (`lengthofm(...) > 0`) осмысленна
  именно для входа без объявленного размера.
- Индексация — с единицы; индексы — переменные: арифметику внутри `[ ]` не
  применять (может не транслироваться).

## Кодогенерация: что не переживает трансляцию

Не переводится в C: `#`, `&`, `..` (syntax.md: «используй циклы»), `string`
(тип), `seterrorstr()` (диагностика — см. ниже), динамические массивы,
матричные операции (`*`, `\`, `./`), прямое присваивание массивов —
копировать поэлементно. Арифметические выражения внутри индексов **могут**
не транслироваться (pitfalls §2.4). Разбор случаев — `pitfalls.md`
(§2.4, §3.1–3.5, §7.1–7.3).

## Диагностика и отладка

- В транслируемом коде `seterrorstr` использовать нельзя (`syntax.md`):
  диагностика — выходным сигналом и `exit`.
- Отлаживают дополнительные выходные сигналы (`dbg_phase`, `dbg_idx`): они
  видны и в расчёте, и в сгенерированном коде.
- После правок прогоняйте «Инструменты → Сгенерировать программу» и
  разбирайте все предупреждения: сообщения указывают объект.
- Без генерации ошибки компиляции скрипта блока наружу (в COM) не выходят —
  признак отказа только косвенный (расчёт не идёт).

## Чек-лист перед кодогенерацией

- [ ] порядок объявлений: входы → выходы → константы → переменные;
- [ ] каждая переменная и порт — с явным типом; массивы статические;
- [ ] нет имён `i`, `j`, `c`; индексы — переменные, без выражений в `[ ]`;
- [ ] деление защищено от нулевого знаменателя (порог вида `1e-12`;
      разбор — `pitfalls.md` §2.1);
- [ ] `sqrt()` — от неотрицательного аргумента (`sqrt(abs(x))`);
- [ ] границы массива проверены перед доступом (§2.3);
- [ ] `while` ограничен счётчиком итераций;
- [ ] однократная загрузка входов — по флагу в теле, не в `initialization`;
- [ ] нет `seterrorstr`, `#`, `&`, `..` и строк;
- [ ] кодогенерация прогнана, предупреждений и ошибок нет.

## Где живёт скрипт блока

Текст скрипта — свойство блока `Script`; он виден в выгрузке модели
(`export_model_text`). MCP-инструменты (mcp#23): `get_block_script` читает
скрипт **снимком выгрузки** — расчёт не запускается, модельное время не
сдвигается; `set_block_script` пишет скрипт и возвращает прежний текст,
число портов до/после и вердикт контура. Внутри записи — та же пара:
`setprop(obj, "script", …)` + **обязательный** `reinitlangblock(obj)` —
без него порты блока не пересобираются, и провода к ним остаются
половинками. Ручная правка через контур страницы (тем же `setprop` +
`reinitlangblock`) — резервный путь, когда инструменты сервера недоступны.
Порты после записи сверяйте: у формы `a[3]: array` пересборка неполна
(раздел «Порты и массивы»). Подключение внешних файлов — `include "имя.inc";`
(форма — справка вендора; в каноне языка не описана, живым прогоном не
проверялась).
